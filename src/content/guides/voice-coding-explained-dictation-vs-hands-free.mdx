"Voice coding" gets used for two quite different activities, and most confusion in articles about it comes from mixing them up.

## Two things with one name

**Dictating to an agent.** You talk, software turns speech into text, and the text goes into a prompt box. A coding agent such as Claude Code, Codex or Cursor does the actual editing. You never say a curly brace. This became popular because agents accept long, loose, natural-language instructions, and talking is a comfortable way to produce those.

**Commanding the editor.** You speak short, structured commands that move the cursor, select code and change it, and you can type no code at all. A command like "chuck bat" deletes the token marked "bat" on screen. This is the older tradition, built for people who cannot use a keyboard comfortably, and it takes real learning time.

If you only read one thing from this guide: start with dictation. It takes minutes to try, costs nothing in most cases, and you will learn quickly whether talking suits you at all.

## Why people do it

Three reasons show up repeatedly.

The first is health. Tavis Rudd's 2013 PyCon talk "Using Python to Code by Voice" is probably the best-known origin story. He described repetitive strain injury so severe that his hands went numb and he could no longer type or work, and he built a voice setup with Python embedded in a speech recognition system.[^1] Talon, covered below, names people with limited hand use as one of its intended audiences.[^2]

The second is speed, though the evidence is narrower than the claims. A Stanford, University of Washington and Baidu study measured speech as 3.0 times faster than keyboard input for English text on smartphones.[^3] That is about typing messages on a touchscreen. It says nothing about writing code on a full keyboard, so do not extrapolate the number to your editor.

The third is that agent prompts are long. Writing three paragraphs of context for an agent by typing is tedious, and speaking it is not. This is the real reason dictation took off in 2025 and 2026, and it is also where voice works best, because errors in a prompt are forgiving. If the transcript says "off" where you said "of", the agent still understands.

## Layer 1: dictation, and how to try it in five minutes

Speech-to-text tools differ mainly in where the audio is processed, how they handle developer vocabulary, and where the text ends up. Here is what the vendors' own pages say.

| Tool | What it is | Facts from the vendor page |
|---|---|---|
| Claude Code `/voice` | Built-in dictation in the Claude Code CLI and its VS Code extension | Audio streams to Anthropic's servers; needs a claude.ai account; no cloud or SSH sessions; transcription does not use Claude messages or count toward `/usage`[^4] |
| Wispr Flow | Dictation app that types into any text field | Free tier with a weekly word cap, Pro $15 a month ($12 billed annually) with no cap; Mac, Windows, iOS, Android. The pricing page does not say whether audio is processed in the cloud or on device[^5] |
| Superwhisper | Dictation app with local and cloud models | Works offline; local models run well on Apple Silicon; default voice model is Whisper Large; free tier with Whisper models, paid Pro tier with cloud models. The page's Pro price was garbled when I read it, so check it yourself[^6] |
| VS Code built-in dictation | Dictation into the editor and chat | The default model "processes microphone audio on your device"; a separate Speech extension exists for platforms without built-in dictation[^7] |
| whisper.cpp | Open source C/C++ port of OpenAI's Whisper, MIT license | Fully offline. The `base` model is 142 MiB on disk and about 388 MB of memory, `small` is 466 MiB and about 852 MB, `large` is 2.9 GiB and about 3.9 GB[^8] |

All five turn speech into text. The practical differences are privacy (does your audio leave the machine), where the text goes (one app or any text field), and how well rare words survive, such as `kubectl` or your company's service names.

### Claude Code, step by step

This is the one I can describe exactly because the documentation is explicit.

1. Run `/voice` inside Claude Code. It runs a microphone check, and on macOS your terminal may trigger the system microphone permission prompt.
2. In the default hold mode, hold `Space` while you talk and release to finish. The transcript lands in the prompt at your cursor and waits for `Enter`. Detection of a held key relies on key-repeat events from your terminal, so there is a short warmup before recording starts.
3. If you prefer, run `/voice tap`. Tap `Space` once to start, speak, tap again to stop and send. Transcripts shorter than three words are inserted but not sent, so an accidental tap does not fire off a stray word.
4. Press `Esc` or `Ctrl+C` to cancel a recording and restore the prompt.
5. To change the key, rebind the `voice:pushToTalk` action in `~/.claude/keybindings.json`. A modifier combination such as `meta+k` starts recording on the first keypress, with no warmup.

The documentation says transcription is tuned for coding vocabulary (`regex`, `OAuth`, `JSON`, `localhost`) and that your project name and git branch name are added as recognition hints automatically.[^4] Dictation uses the same `language` setting as Claude's responses, defaulting to English, and Korean is among the 20 supported languages along with Japanese, German, French and Spanish.

Limits worth knowing before you build a habit on it: it does not work over SSH, in Claude Code's cloud sessions or in VS Code Remote sessions, because the microphone is on your local machine. It also stops by itself after 15 seconds of silence or two minutes in total.[^4]

### What to say

Dictation works best when you say what you want, not how the code should look. "Add a retry with exponential backoff to the fetch call in the sync module, and keep the timeout at ten seconds" is a good spoken prompt. "Open paren, user, comma, ..." is not, and nothing in these tools is meant for it. When a specific identifier matters, say its name once and check the written transcript before you press Enter. That check costs seconds and saves a confusing diff.

## Layer 2: commanding the editor with Talon and Cursorless

This is a different learning curve. **Talon** is a hands-free input replacement for keyboard and mouse, free to use and funded by Patreon, with downloads for macOS, Windows and Linux (X11).[^2][^9] Its site lists voice commands, dictation, mouse control by looking (with an eye tracker) and noises: "pop to click, hiss to scroll".[^9]

On a mirror of the Talon wiki, the recommended speech engine is the free Conformer model, with Dragon as a paid alternative. The same page says that as of April 2024 the main Conformer model supports English only.[^10] I could not read the live wiki, so check that before relying on it if you speak another language.

**Cursorless** sits on top of Talon in VS Code. It puts a small colored "hat" over each token on screen and lets you refer to a token by saying the hat's color and letter. The documentation describes every command as an action plus a target: in "take air", the action "take" selects the token that has the "air" hat, and "chuck bat" deletes the token that has the "bat" hat.[^11] It is MIT licensed and depends on Talon for now.[^12]

The reward is that editing becomes a short sentence. The cost is that you learn a vocabulary of commands, like learning vim, and you will be slower than at the keyboard for a long time. For people who cannot type comfortably, that trade is clearly worth it. For everyone else, it is a hobby with a payoff.

## Where it breaks

- **Privacy.** Some tools send audio to a server. Claude Code's does, by its own documentation. Local options exist (whisper.cpp, Superwhisper's offline models, VS Code's default dictation model) if that matters for your work.
- **Shared rooms.** In an open office, speaking prompts aloud is a social problem before it is a technical one. Tap mode and a good headset help, but not completely.
- **Remote work.** Claude Code's voice mode does not work over SSH or inside remote dev environments, because it records from the machine the terminal runs on. A system-wide dictation app avoids that by sitting in front of whichever terminal you are using.
- **Rare words.** Names of your own services, libraries released last month and non-English identifiers are where recognition fails first. Custom vocabulary features exist in some apps, and I did not test how well any of them work.
- **Staleness.** This area churns. One status roundup from August 2026 lists several older tools as dead or dormant, including VoiceCode.io, Mozilla's DeepSpeech and Silvius, and says Serenade's development effectively stopped around 2022. Its author sells a competing dictation app, so read it with that in mind.[^13] Separately, Serenade's open source repository does exist, and I could not confirm its current activity either way.

## Where to start

- **You are curious, and you use an agent daily:** try `/voice tap` in Claude Code for a week. Say whole sentences. Read the transcript before sending.
- **You work in several agents or apps:** try a system-wide dictation app with a free tier, such as Wispr Flow or Superwhisper, so one habit works everywhere.
- **Audio must stay on your machine:** use a local model (Superwhisper offline, VS Code's default, or whisper.cpp if you like building things).
- **You need to reduce keyboard and mouse use, or already have pain:** start with Talon and its community command set, add Cursorless once the basics feel natural, and expect weeks of practice. Ask the community on the Talon Slack, which the wiki names as its recommended support channel.[^2]
