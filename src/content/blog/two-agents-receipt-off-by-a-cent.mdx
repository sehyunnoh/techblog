Two posts in this series measured what an [isolation boundary costs](/posts/subagent-costs-34000-tokens) and [what's inside that cost](/posts/agent-identity-costs-104-tokens). Neither one produced a single bug. That wasn't skill — both experiments were read-only and deterministic by design, so every arm returned the identical answer no matter how many agents touched it. MAST, the largest published taxonomy of multi-agent failure, names **14 distinct failure modes** across three categories.[^1] My first two experiments were structurally incapable of triggering any of them, because none of the 14 has anything to do with an agent counting words correctly.

This one does. I gave two isolated subagents the two halves of one deliverable — the shape of Cognition's now-familiar Flappy Bird anecdote, a bird drawn in one style glued to a background drawn in another[^2] — and let them write real files with no channel between them. One half didn't compile. The fixed version compiled, ran, and produced a receipt that looked completely reasonable. It was silently wrong by a cent.

## MAST, briefly

MAST was built from 150 hand-annotated multi-agent traces at inter-annotator agreement κ = 0.88, then extended to 1,600+ traces across seven frameworks — ChatDev, MetaGPT, HyperAgent, AppWorld, AG2, Magentic-One, OpenManus.[^1] It sorts every failure it found into three categories: **system design issues** (5 modes — a single agent disobeying its own spec, repeating steps, losing history), **inter-agent misalignment** (6 modes — agents talking past each other, resetting a conversation, ignoring input), and **task verification** (3 modes — nobody checking the work, or checking it wrong).

The middle category is the one that matters here, and it's the one my first two posts couldn't reach: it requires two agents to actually interact. A read-only fan-out where every shard reports back an independent number has no dialogue to misalign.

## The experiment

One deliverable, split down an interface no one wrote down: a receipt-printing module for a point-of-sale system, needing a line-item formatter and a total/tax calculator that both consume the same cart. Two fresh `general-purpose` subagents, launched from a single message so neither could see the other start, each given only its own half of the spec and told the module was "brand new, no existing code to match."[^4]

## What converged

The first surprise is what the two agents agreed on without ever comparing notes. Agent A's `LineItem` and Agent B's `PurchasedItem` are structurally identical: `name: string`, `quantity: number`, `unitPrice: number`, both in whole dollars. Different type name, same three fields, same types, same units. For a domain this well-trodden, two independent runs landed on the same "obvious" shape — implicit decisions don't conflict uniformly across a task, they cluster where there's no obvious convention to fall back on. Money formatting and module boundaries turned out to be exactly that kind of place.

## Failure 1: it doesn't compile

Agent A's file, in full save for comments:

```ts
interface LineItem {
  name: string;
  quantity: number;
  unitPrice: number;
}

function formatLineItems(items: LineItem[]): string[] {
  // ...
}
```

Agent B's:

```ts
export interface PurchasedItem {
  name: string;
  unitPrice: number;
  quantity: number;
}

export function formatTotal(items: PurchasedItem[], taxRate: number): string {
  // ...
}
```

Both agents were told to keep their file "self-contained — no imports from other project files." Agent B read that as a constraint on what it *consumes*. Agent A read it as a constraint on what it *produces*, and exported nothing at all. Importing `formatLineItems` anywhere else fails before a single line of logic runs:

```
integration.ts:1:43 - error TS2306: File 'lineitems.ts' is not a module.
```

Real error, from this repository's own TypeScript compiler (v6.0.3) run in strict mode against both files unmodified.[^4] Neither agent violated its instructions. Assembled, the module doesn't exist.

## Failure 2: it compiles, runs, and lies by a cent

Two `export` keywords fix the compile error. What's left is a structurally sound module — and the two functions still disagree on something neither of them wrote down: **where to round**.

Agent A rounds per line, for display:

```ts
const lineTotal = formatCurrency(item.quantity * item.unitPrice); // toFixed(2), per line
```

Agent B sums the raw, unrounded values first and rounds once, at the very end:

```ts
const subtotal = items.reduce((sum, i) => sum + i.unitPrice * i.quantity, 0);
// ...formatMoney(subtotal) — toFixed(2) happens once, after the sum
```

Run both against the original sample cart — $9.00 espresso beans, $4.50 oat milk — and the receipt looks perfect: line items sum to $22.50, subtotal reads $22.50, everything reconciles. If I'd stopped there and called the module verified, that's MAST's **FM-3.3, incorrect verification**[^1] in miniature: I checked the output, on data too clean to expose the disagreement.

Three items at $0.125 each is not clean:

```
$ node -e "..."
per-line displayed: [ '0.13', '0.13', '0.13' ]  → a customer adding by eye gets $0.39
raw subtotal 0.375 → displayed subtotal            $0.38
```

The line items say $0.39. The subtotal says $0.38. Both numbers are the honest output of correct, tested-in-isolation code. Neither agent is wrong on its own terms. Assembled, the receipt doesn't add up — by exactly the kind of small, plausible, easy-to-miss margin that erodes trust in a payments system.

Isolation doesn't stop conflicting decisions — Cognition already showed that without a shred of MAST's vocabulary. What isolation does is move *where the failure can be observed*. Six of MAST's 14 modes live in a category that presupposes two agents talking to each other mid-task. Parallel subagents on this harness don't talk to each other at all, mid-task or otherwise — [the previous post in this series](/posts/subagent-costs-34000-tokens) measured that directly: 0-byte transcript files, 0 sidechain records, for eight subagents that ran side by side. There is no wire for FM-2.1 through FM-2.6 to travel on. That's not a safety property. It's a redirection: every failure that inter-agent misalignment would have caused instead shows up as an agent quietly over- or under-interpreting a spec it never got to check against anyone else's (FC1), or as a verification step that either didn't happen or didn't happen against the right data (FC3). Both of the bugs above are exactly that — one in each of the two categories isolation didn't block.

**98,856 tokens** produced two files that, delivered as-is, did not compile together. Neither number includes the integration step: reading both files, writing the driver, running `tsc`, then — the part that actually mattered — thinking of an input adversarial enough to expose the rounding disagreement. That last step is not a boundary crossing the harness bills you for. It is judgment, and nothing about spawning two agents in parallel supplies it for free.

Type-level verification is nearly free by comparison: `tsc --strict` caught Failure 1 in about a second, no model involved, the moment a driver file tried to import both modules. That's the cheap half of MAST's task-verification category, and it's the half most CI pipelines already run. Failure 2 is the expensive half — no type checker flags it, because both functions are individually well-typed and individually correct. It only surfaces if someone runs the combined system against a value neither agent happened to pick, which is precisely the class of check that Anthropic's own guidance singles out a *verifier* subagent for: a reader with no access to either writer's reasoning, whose only job is to try to break what they built.[^3]

## Trade-offs

**Convergence is not proof of compatibility.** The item shape matched by coincidence of domain familiarity, not by design, and that made it easy to assume the rest matched too. It didn't.

**Cheap verification and expensive verification catch different bugs.** A compiler catches structural mismatches for the cost of a CI step. It does not catch two internally-correct rounding strategies disagreeing by a cent — that requires someone to go looking for adversarial input, which is exactly the work an isolated writer has no reason to do and an isolated reviewer has every reason to do.

**One task, one pair of agents, one model generation.** The subagent model here was left at the harness default rather than pinned to Haiku 4.5 as in the read-only baseline, so the token chart above compares harness and agent type cleanly but not model-for-model. The qualitative shape — a loud compile failure plus a silent semantic one — is the kind of result I'd expect to generalize across models; the exact one-cent gap is a property of this specific input, not a universal constant.

**The taxonomy's shape is itself informative.** Six of MAST's 14 modes require a conversation this harness's parallel subagents structurally don't have. That's worth knowing before reaching for a mitigation built for a failure category that can't occur on the system you're running.

## Takeaways

- **Isolation relocates conflicting decisions; it doesn't remove them.** Two agents with zero shared context and zero communication still produced two artifacts that didn't compose — a compile-time failure and a silent one-cent semantic disagreement.
- **Six of MAST's 14 failure modes need a channel this harness's subagents don't have.** Inter-Agent Misalignment presupposes agents that talk mid-task. Parallel subagents here have 0-byte transcripts and 0 sidechain records — there is no wire for FM-2.1 through FM-2.6 to travel on, so all of the risk this experiment found landed in System Design and Task Verification instead.
- **A passing integration test is not verification — it's verification against whatever data you happened to try.** The receipt looked perfect on the original sample cart. It broke on the first adversarial input I tried on purpose.
- **Type checking is the free 10% of verification.** It caught the compile failure instantly, for the price of a CI step. The semantic failure needed a human — or a dedicated verifier agent — to go looking for it.
- **Convergence on the "obvious" parts of a shared domain is real, and it's a trap.** Two agents independently choosing the same field names for a receipt item is a fact about how well-trodden that shape is, not a fact about whether the rest of the contract holds.
